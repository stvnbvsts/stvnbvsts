# GitHub profile README ideas for Steve

The purple typing banner introduces Steve as a developer, frustrated musician, and bike enthusiast. The stock GitHub prompts carry most of the jokes. Replacing that list with a few projects would give visitors something to explore, and the “headbanger” badge could still work as a punchline. [Current profile README](../README.md)

## What people put on their profiles

- **An intro with handpicked work.** Cassidy Williams pairs a conversational bio and a few personal interests with links to things she made. Denys Dovhan explains the tools he builds at work and the automations he builds at home. Both formats need an edit when the work or links change. [Cassidy’s README](https://github.com/cassidoo/cassidoo#readme), [Denys’s README](https://github.com/denysdovhan/denysdovhan#readme)
- **A visual theme.** Sindre Sorhus uses retro-web GIFs checked into his repo, alongside links to his app and writing. Navi turns the profile into a terminal with an ASCII portrait and a Neofetch-style card. The static visuals can ship as repo files. Navi’s live contribution heatmap also runs on a schedule. [Sindre’s README](https://github.com/sindresorhus/sindresorhus#readme), [Navi’s README](https://github.com/navi3582/navi3582#readme), [Navi’s implementation](https://github.com/navi3582/animated-github-profile#readme)
- **A feed or a generated widget.** Simon Willison’s Action writes recent releases, blog posts, and TILs into the README. Platane animates a snake across the contribution grid. Hosted cards offer quick setup, though GitHub Readme Stats describes its shared endpoint as best-effort. A workflow can generate a file in the profile repo and refresh it periodically. [Simon’s README](https://github.com/simonw/simonw#readme), [Simon’s workflow write-up](https://simonwillison.net/2020/Jul/10/self-updating-profile-readme/), [Platane’s README](https://github.com/Platane/Platane#readme), [GitHub Readme Stats](https://github.com/anuraghazra/github-readme-stats#deploy-on-your-own)
- **Something visitors can play.** Tim Burgan lets visitors submit chess moves through prefilled GitHub issues. A workflow updates the board in the README. The profile doubles as a demo, with game state and incoming issues to maintain. [Tim’s README](https://github.com/timburgan/timburgan#readme)

## Directions that fit this profile

1. **Gig poster.** Lead with a short plain-text intro, a purple gig-poster graphic, and a featured link to Gigtape, the Go project that turns setlist.fm data into Spotify playlists. A setlist-style demo image or example playlist gives people something concrete to explore. Link to the dotfiles and the Zsh theme as smaller projects, and put the personal site on its own line. [Gigtape](https://github.com/stvnbvsts/gigtape#readme), [Dotfiles](https://github.com/stvnbvsts/dotfiles#readme), [boringaf Zsh theme](https://github.com/stvnbvsts/boringaf-zsh-theme#readme), [Personal site](https://stvnbvsts.github.io/)
2. **Terminal intro.** Give the shell projects a visual role with a small screenshot of the actual Zsh theme or a short `whoami`-style text block. Follow it with the same project links and keep one line about music and bikes. GitHub supports repo-relative images with alt text and `<picture>` for theme variants. [boringaf Zsh theme](https://github.com/stvnbvsts/boringaf-zsh-theme#readme), [GitHub image syntax](https://docs.github.com/en/get-started/writing-on-github/getting-started-with-writing-and-formatting-on-github/basic-writing-and-formatting-syntax#images), [GitHub’s theme example](https://docs.github.com/en/get-started/writing-on-github/getting-started-with-writing-and-formatting-on-github/quickstart-for-writing-on-github)
3. **Short project log.** Keep the intro and featured projects, then add one dated note about something that shipped or something interesting learned while building it. The first entry could explain how Gigtape handles songs it can’t match on Spotify. Update it by hand and automate releases later if the project has a steady release cadence. [Gigtape](https://github.com/stvnbvsts/gigtape#readme), [Simon’s README](https://github.com/simonw/simonw#readme)

I’d start with the gig poster and pin Gigtape so it’s easy to find. Music already connects Steve’s intro to something he built, and a graphic stored in the repo keeps the visual design self-contained. [Gigtape](https://github.com/stvnbvsts/gigtape#readme), [GitHub profile pins](https://docs.github.com/en/account-and-profile/how-tos/profile-customization/pinning-items-to-your-profile)
